# Modern RL and post-training exercise leads

Surveyed 2026-10-06. This note maps primary research to **original** dojo coding tasks. It is a practice design aid, not a reproduction of any paper's full training system. `dojo/0037_dpo_loss.py`, `0038_grpo_loss.py`, `0039_ppo_loss.py`, and `0041_opd_loss.py` already teach compact loss contracts; `0040_linear_regression.py` is unrelated to this sequence. Deep-ML's [GRPO problem 101](https://www.deep-ml.com/problems/101) also overlaps the current GRPO warm-up. The [Deep-ML survey](deep-ml-question-survey.md) records that overlap and its first-party catalog provenance.

Four selected exercises are now runnable as [DPO token pairs](../../dojo/0085_dpo_token_pairs.py), [PPO GAE](../../dojo/0086_ppo_gae.py), [GRPO tokens](../../dojo/0087_grpo_tokens.py), and [student-rollout OPD](../../dojo/0088_opd_rollout.py). The longer training-step ideas below remain research leads.

## What the sources actually establish

| Method | Algorithmic core and boundary | Primary source |
| --- | --- | --- |
| PPO | Sample with an old policy, then optimize a clipped importance-ratio surrogate over minibatches for multiple epochs. Advantage estimation and value learning are separate from the surrogate; GAE uses discounted TD residuals and a value baseline. A clipped surrogate alone is not a PPO training loop. | [PPO paper](https://arxiv.org/abs/1707.06347); [GAE paper](https://arxiv.org/abs/1506.02438); [DeepSeekMath PPO formulation](https://arxiv.org/html/2402.03300#S4.SS1.SSS1) |
| GRPO | For each prompt, sample a group of completions from the old policy, compute group-relative rewards, and apply a token-level clipped importance-ratio objective plus reference-policy KL control. The original outcome-supervision variant normalizes rewards within each prompt group and avoids a learned critic. Completion-length normalization is part of the published objective. | [DeepSeekMath §4.1](https://arxiv.org/html/2402.03300#S4.SS1) |
| DPO | Fit pairs of preferred and dispreferred completions through a logistic objective on **sequence** log-probability gaps, adjusted by a fixed reference policy. The Bradley–Terry derivation cancels the prompt-dependent partition function. This uses a fixed preference dataset; it does not require a policy rollout or critic for each optimization step. | [DPO paper §§4–5 and Appendix A.2](https://arxiv.org/html/2305.18290) |
| OPD | The key data contract is that the student generates trajectories and the teacher scores the student-visited prefixes. On-policy distillation can use different token-level divergences: the original GKD framework allows forward KL, reverse KL, or other choices and mixes fixed and student-generated data. Recent OPD work studies reverse KL at student-visited states, including full-vocabulary, sampled-token, and top-k supervision. Thus, **reverse KL is a chosen OPD variant, not the definition of on-policy data**. | [GKD paper §3.1](https://arxiv.org/html/2306.13649#S3.SS1); [Rethinking OPD §3](https://arxiv.org/html/2604.13016); [Entropy-aware OPD](https://proceedings.mlr.press/v306/jin26e.html) |

## Recommended bite-sized scripts, in teaching order

Every item below is an **authored exercise choice**. The citations motivate the mechanism; shapes, edge policies, and staged checks are dojo design decisions. Use one top-level question script with a tagged editable answer cell and one `_eval.py` reference script per exercise, following the repo's Emacs/Jupyter workflow.

1. **Completion-only token log-probabilities** (`[B,T,V]` logits, tokens, completion mask → `[B]` sequence sums and `[B,T]` token log-probs). Baseline: gather from stable `log_softmax`. Follow-ups: exclude prompt/padding, shift next-token labels correctly, handle empty completion and EOS. Production: mixed lengths and finite gradients. This is the missing input adapter for `0037` and `0038`, and makes their sequence-versus-token reductions explicit. [DPO](https://arxiv.org/html/2305.18290); [DeepSeekMath](https://arxiv.org/html/2402.03300#S4.SS1).
2. **Preference pair DPO step** (paired prompt/completion logits from policy and frozen reference → loss and diagnostics). Baseline: compose sequence log-probs with `0037`'s gap formula. Follow-ups: shared prompt exclusion, swapped-pair symmetry, chosen/rejected reward margins, one optimizer step that improves a tiny fixed pair. Production: valid-token masking and no gradient into the reference. This extends `0037` from precomputed scalar log-probs to a meaningful training slice. [DPO paper](https://arxiv.org/html/2305.18290).
3. **Generalized advantage estimation** (`[B,T]` rewards, values, terminals, valid mask, last bootstrap value → advantages and return targets). Baseline: one trajectory reverse scan. Follow-ups: terminated versus time-limit truncated, ragged batches, γ/λ limits. Production: no reward leakage across episode boundaries; compare hand-computed traces. This supplies the missing estimator for `0039`. [GAE paper](https://arxiv.org/abs/1506.02438); [DeepSeekMath PPO description](https://arxiv.org/html/2402.03300#S4.SS1.SSS1).
4. **One PPO minibatch update** (frozen old log-probs, GAE advantages, value targets, fresh policy/value outputs → policy and value losses, clip fraction, approximate KL). Baseline: connect GAE to `0039`. Follow-ups: two optimization epochs on the *same* rollout while keeping old quantities fixed; early stop on a stated KL threshold. Production: action mask and explicit normalization; deterministic tiny-bandit improvement. KL threshold, diagnostic estimator, and value-loss coefficient are authored choices, not mandates of the PPO paper. [PPO paper](https://arxiv.org/abs/1707.06347).
5. **Grouped completion GRPO step** (prompt IDs, rewards, old/current/reference token log-probs, masks → grouped advantages, clipped objective, KL estimate). Baseline: compose `0038`'s group normalization with `0039`'s clipped ratios. Follow-ups: unequal completion lengths, constant-reward group, one prompt with no valid completions, reference detached. Production: show how per-completion averaging and global-token averaging yield different results; choose and document one rather than silently equating them. The first is in DeepSeekMath; alternatives are documented by [TRL's official trainer](https://github.com/huggingface/trl/blob/main/docs/source/grpo_trainer.md) and are not all the original GRPO objective. [DeepSeekMath §4.1](https://arxiv.org/html/2402.03300#S4.SS1).
6. **Student-rollout OPD step** (tiny categorical autoregressive student and frozen teacher). Baseline: sample a student continuation, query teacher logits at exactly those visited prefixes, then apply `0041`'s reverse KL. Follow-ups: variable stopping and masks; compare teacher-forced prefixes versus student prefixes; confirm gradients do not enter teacher or discrete sampling. Production: recompute current student logits on saved rollout prefixes and specify staleness policy. This is the most important missing contract in `0041`, which currently only compares logits at supplied positions. [GKD §3.1](https://arxiv.org/html/2306.13649#S3.SS1); [Rethinking OPD](https://arxiv.org/html/2604.13016).
7. **OPD supervision granularity** (optional advanced exercise: full-vocabulary reverse KL versus sampled-token estimate on the same student-visited states). Baseline: exact categorical KL. Follow-ups: Monte Carlo bias/variance measurement; top-k truncation with an explicit renormalization policy; high-entropy teacher case and forward-KL comparison. Production: memory accounting for `[B,T,V]`. Beware that a sampled token's log-ratio is an unbiased *value* estimate of a fixed-state KL, while naively differentiating through that sampled scalar does not automatically produce the exact full-vocabulary gradient. [Rethinking OPD §3](https://arxiv.org/html/2604.13016); [Entropy-aware OPD](https://proceedings.mlr.press/v306/jin26e.html).

### Scope note

This sequence prioritizes data provenance, masks, frozen-versus-trainable quantities, reduction denominators, and one real update. Full model serving, distributed rollout workers, reward modeling, and benchmark reproduction would swamp a bite-sized dojo exercise. The existing files can remain as useful prerequisite loss drills; the new scripts should make the pipeline stages observable with small deterministic examples rather than relabeling the current scalar losses as complete PPO/GRPO/OPD implementations.
